# Well-known services, by host. Format:  <host-suffix> | <who runs it> | <what it is> [| shared]
# A host matches an entry when it equals it or ends with "." + it.
#
# What this list is for (host reputation, user decisions 2026-11-12): a name for a host.
# The panel and the report say who runs an address ("api.together.xyz: Together AI"), and
# the "Trust this address?" box shows it as a hint for the user's own decision.
# It never changes a host's class (declared, undeclared, ...), the possible-exfil
# correlation, any finding or any score. (0.8.0 lowered one GuardDog heuristic from this
# list by itself; the user chose to decide per address instead, 0.9.0.)
#
# Rules for adding a line (tests/test_known.py enforces the ones a test can):
#   - one operator runs the whole suffix. Never a place where anyone can sign up and get a
#     drop box under it: paste sites, request catchers, tunnels, chat webhooks, free app
#     hosting, file buckets, URL shorteners. Those live in endpoint_hosts.txt and stay
#     findings or context there; no suffix here may overlap its exfil_service, messaging,
#     developer_hosted or analytics entries.
#   - mark it `shared` when customers get their own host under the suffix
#     (<name>.openai.azure.com); the text should say so.
#   - prefer the exact API host over a whole company domain.
#   - "what it is" is a few plain words; it is shown to the user as written.
